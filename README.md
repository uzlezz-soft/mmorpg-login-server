# MMORPG Login Server

Небольшой backend для MMORPG, который выступает промежуточным сервером между
клиентом игры и игровыми серверами. Он отвечает за регистрацию и авторизацию
пользователей, выдачу токенов, выбор игрового сервера, загрузку персонажей и
проверку банов.

> Проект был сделан на коленке за неделю, чтобы не сдавать зачёт, на 2 курсе.

## Возможности

- регистрация и вход пользователей;
- JWT-токены для авторизации и отдельные session-токены для подключения к игровому серверу;
- регистрация игровых серверов и отслеживание их состояния через heartbeat;
- получение списка доступных серверов по версии игры;
- создание, просмотр, обновление и удаление персонажей;
- временные и постоянные баны пользователей.

## Архитектура

Приложение написано на **Python** с использованием **FastAPI**, **SQLAlchemy**
и **Pydantic**. Точка входа — `app/main.py`, где создаётся FastAPI-приложение,
инициализируются таблицы и подключаются роутеры.

Структура `app/` разделена по ответственности:

- `routers/` — HTTP-эндпоинты FastAPI (`/user`, `/server`, `/character`, `/ban`);
- `services/` — основная бизнес-логика;
- `crud/` — операции чтения и изменения данных в базе;
- `models/` — SQLAlchemy-модели таблиц пользователей, серверов, персонажей и банов;
- `schemas/` — Pydantic-схемы запросов и ответов;
- `utils/` — JWT, хеширование паролей и проверка доверенных IP;
- `config.py` и `database.py` — настройки и подключение к базе данных.

Игровой сервер взаимодействует с login server через специальные эндпоинты:
сообщает о запуске, отправляет heartbeat, подтверждает подключение игрока и
передаёт обновления персонажей.

## Запуск

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload --host 0.0.0.0 --port 4444
```

Настройки читаются из `.env`. Основные параметры — `DATABASE_URL`, секреты JWT,
таймаут heartbeat и список доверенных IP игровых серверов. Если `DATABASE_URL`
не задан, используется локальная SQLite-база `temp.db`.

После запуска интерактивная документация доступна по адресу `/docs`.
